Step 3 · Packaging for vLLM

Four decisions, no build step

1 · Does vLLM know the architecture?

Look up config.json's architectures in vLLM's supported-models list and note the first version that supports it. Gemma 4 needs vLLM ≥ 0.24; the current worker ships 0.30.

2 · Which worker image?

runpod/worker-v1-vllm = official vllm-openai image + a serverless wrapper. Every UPPERCASED env var becomes an engine flag: MAX_MODEL_LEN → --max-model-len.

3 · Which GPU and precision?

Weights + KV cache must fit. 10 GB bf16 fits a 24 GB RTX 4090 with 10.7 GB left for cache. A 9B needs FP8 to fit 24 GB; a 14B needs FP8 or 48 GB.

4 · Do you need to bake anything?

Only when a system package is missing. Two-line Dockerfile FROM the worker, built by GitHub Actions to GHCR. Installing at container start blew the cold-start window (6 min).

Two Gemma 4 gotchas, both solved with engine flags

MODEL_LOADER_EXTRA_CONFIG={"enable_weights_track": false}  · KV-shared layers 15–34 have no k/v weights; the strict loader check must be relaxed

MM_PROCESSOR_KWARGS={"max_length": 480000, "truncation": true}  · transformers audio processor bug; clips ≤ 30 s
