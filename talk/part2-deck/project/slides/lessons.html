Lessons from running Sunflower in production

Eight things we learned the expensive way

Verify with a real request, every deploy

A ready worker is not a working endpoint. Verification caught FP8-on-Ampere turning the 14B into gibberish before users did.

First touch through the queue

The sync OpenAI route sits behind a ~100 s edge timeout. Cold calls there fail with 524; /run never does.

Pin the commit; the cache does anyway

New weights on the Hub do not reach the endpoint. Re-pin deliberately and watch placement: a stalled rollout cost 45 minutes of downtime.

Do not pin a data centre

A network volume locks workers to one region and starved GPU supply. The host model cache gives caching without the pin.

Set a CUDA floor

A CUDA 13 image on an old-driver host crash-loops with no error in the console. min-cuda-version 13.0.

Bake, never install at start

A 6-minute pip install blew the cold-start window and workers were recycled mid-install. Two-line Dockerfile, GitHub Actions, done.

Match quantization to the GPU

FP8 needs Ada or Hopper. Keep gated-repo tokens scoped and watch what the worker logs at start-up.

Follow the model card

Fixed translation template, temperature 0, thinking off where the model reasons. Free-form prompts produced artifacts.
