Prefill, decode and the KV cache

Step 1

Tokens

The model splits text into tokens, roughly word pieces.

Step 2

Prefill

Reads the whole prompt once before writing anything.

Step 3

Decode

Writes the reply one token at a time, each step reading everything before it.

The KV cache

one entry per token, kept for the life of the request

■ prompt tokens (prefill)

■ generated tokens (decode)

□ still to come, size unknown in advance

Without the cache every new token would recompute all the earlier work. With it, memory grows with every token of every active request.
