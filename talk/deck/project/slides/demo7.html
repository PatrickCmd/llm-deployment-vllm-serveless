Tuning the knobs for your workload

python task_7_tuning.py

Three server configurations, each benchmarked with 10 concurrent requests of 50 tokens.

Configmax_model_lenmax_num_seqsThroughput
A: Default128256316.6 tok/s
B: Shorter context64256323.9 tok/s
C: Limited concurrency648279.9 tok/s

Config C has the lowest latency per request (1.38s) but the lowest total throughput. There is no single best setting.

--max-model-len

Longest context per request. Lower means less KV cache per user, so more users fit.

--max-num-seqs

How many sequences run in one batch. Trades per-request latency for total throughput.

--gpu-memory-utilization

Share of GPU memory vLLM may claim for weights plus KV cache blocks.

Measure with your own prompts and traffic shape before you pick.
